### 知识闭环优化（第一批）

在项目中打开“项目知识与应用”，按“选择/新建知识空间 → 上传 → 等待解析 → 核对片段 → 发布供原文检索”操作。责任人可查看真实解析次数、恢复等待与重试提示；共享成员只看授权发布资料，不获得任务内部信息或维护权限。

## 以下为GitHub原版历史说明（不作为整合版启动步骤）

密灯做两件事：**把公司的资料变成能查来源的问答；把跨部门交接变成有责任、有版本、有验收的记录。**

例如，市场录入客户需求，商务确认并发布，设计按同一版本提交方案和料表，采购验收后登记交期。需求变了，系统提示旧交付需要复核，避免继续拿旧料表办事。

## Windows 启动

需要 Node.js（含 npm）、Python 3.12、uv 和 Git。克隆仓库后，在项目根目录双击 **`启动密灯.cmd`**，或用 PowerShell：

```powershell
.\scripts\start-local.ps1
```

脚本安装锁定依赖、构建前端，再启动真实后端。启动成功后打开 <http://127.0.0.1:8000>。关闭运行窗口会停止服务。首次安装需要联网，后续可用 `-SkipBuild` 跳过前端构建。

macOS / Linux：

```sh
./scripts/start-local.sh
```

首次启动在 `backend/.runtime/bootstrap-passwords.json` 本地生成 `admin`、`manager` 两个随机口令。管理员可配置服务和授权项目成员；知识库管理人员维护知识；普通使用者可免口令进入。**不要把口令文件、`.env` 或整个 `.runtime` 上传 GitHub。**

也可以首次启动前复制 `backend/.env.example` 为 `backend/.env`，设置至少 10 位的 `ADMIN_PASSWORD` / `MANAGER_PASSWORD`。已有数据库不会因修改环境变量而覆盖口令；登录系统设置修改已有口令。

## 第一次跑协同流程

1. 管理员进入“协同工作台”，建立项目，明确流程责任人、数据责任人。
2. 同事在自己的浏览器进入协同页，复制身份编号给管理员。管理员在该项目“成员授权”中选择姓名和业务角色。同事刷新后可见被授权项目。
3. 市场录入需求 → 商务确认发布 → 设计回写方案 → 设计建立契约、登记料表、提交交付证据 → 采购按质量规则验收，再登记采购进度及原系统凭证。
4. 商务登记需求变更后，发布新版本；设计重新回写方案、提交交付并复核料表；采购重新验收。已发生的订单事实保留，实际取消、替换订单需在原系统人工处理。
5. 项目经理查看例外、登记人工决策、责任人和期限，完成后补充结果证据。需要交接时导出项目记录。

管理员可以选择五个工作角色走合成资料演练。其他人只能选择服务器授予的角色。撤销授权后，下一次请求即无权访问。当前身份绑定浏览器会话，尚未接入飞书实名登录、企业 SSO、部门组织和人员目录；会话到期（默认 8 小时）、清理浏览器或更换设备后可能产生新身份，需要重新授权。共享管理口令不能替代企业实名账号。

历史协同数据会自动归入独立项目，内容保留，默认仅管理员可见。请管理员核对责任人、授权成员，并重新核对历史交付依据。首次启动不再自动生成仿真的公司业务数据。

## 知识库与真实模型

管理员在“模型与服务”添加连接和实际模型 ID，填写 API Key 后显式测试，再给知识库选 Embedding。密钥加密保存在服务端，接口不返回明文。模型测试和问答会调用配置的实际服务，云模型可能产生费用。

基本路径：新建知识库 → 上传资料 → 任务中心查看进度 → 检查片段 → 发布索引 → 检索测试 → 问答 → 点击来源。

支持 Word、PDF、Markdown、图片、Excel、CSV 等。普通文本和表格可先解析检查，发布索引需要可用向量模型；扫描 PDF / 图片的 OCR 或视觉能力仍需相应服务。缺少配置会明确失败。Excel 用于检索和引用，不执行宏，也不替代财务精确计算。

模型支持按实际连接配置 LLM、Embedding、Rerank、Vision；向量空间变化需新建配置并重建索引。可使用兼容服务的本地模型。访问本机 / 私网模型前需显式启用 `ALLOW_PRIVATE_PROVIDERS=true`。原始敏感资料是否可发送外部服务，由企业的数据权限和服务配置决定。

应用画布支持开始、检索、生成、条件、模板、输出节点；草稿调试后发布。RAG 工作台的扩展范围和待接入项见 [集成说明](integrations/README.md)。

## 部署与备份

技术栈：FastAPI、SQLAlchemy、LangChain、Qdrant、React、Ant Design。默认本地配置是 SQLite、Qdrant 本地目录和单 API 进程的持久任务执行器。不要同时让多个进程访问同一个 Qdrant 本地目录。

`compose.yaml` 提供 PostgreSQL 17、Qdrant、Redis、Celery 和 API/前端同源部署：

```sh
cp .env.compose.example .env
# 填写自己的随机 POSTGRES_PASSWORD、稳定的 SECRET_KEY 和实际来源地址。
docker compose up --build -d
```

本轮未在 Docker 中验证，不应把本地 SQLite 验收等同于多人生产部署验收。局域网 / 互联网访问前需配置 HTTPS、真实来源、人员身份、最小权限和备份恢复。

本地备份先停止 API 及任务，再完整复制当前 `DATA_DIR`（默认 `backend/.runtime`），包含数据库、原件、解析结果、向量和加密密钥。只复制 SQLite 主文件不保证完整恢复。Compose 需分别备份 PostgreSQL、Qdrant、应用数据及稳定的加密密钥。

## 当前边界

这是一套可本地运行和试点的知识与协同系统。尚未接通用友 / ERP、MES、成本账、电子签章或飞书自动通知；页面中的采购状态是人工登记。协同中的方案和决策由人确认，AI 不代替技术、财务或安全审批。多组织实名授权、复杂订单变更、规模并发与灾备恢复仍需进一步工程验证。

### 知识问答工作台（本机优化批）

完整本机版首页提供项目选择、问题输入、已发布原文来源和相关业务按钮。问答使用本地关键词匹配，不调用模型，不代替业务确认；无命中会明确提示。部门与岗位协作区展示十个既有项目岗位并标记本人岗位，独立部门组织树尚未实现；成员与岗位配置已有独立入口，原有七类业务、待办和项目空间保留。

新增只读 `POST /api/projects/{pid}/workspace/ask`，请求 `{query}`（1—1000字），返回 `project_id/query/mode/model_enabled/keywords/sources/entries/notice`。来源最多6段，每段最多1000字，按项目成员、空间共享和发布状态实时筛选。403/404/401及422沿用统一错误结构；没有业务写入和持久化问答历史。

### 规则应用与固定用例（第二批）

项目知识与应用 → 选择知识空间 → 规则应用。责任人填写1—20条固定测试输入与预期，先点击“核对测试结果”，查看实际输出及逐节点状态，再人工“确认发布当前草稿”。更改草稿或用例会使旧通过报告失去发布资格，服务端发布时重新执行并校验版本；共享成员只运行发布版。最近50条本人运行/评测记录保留在原数据库，可下载JSON；回退保留当前草稿与历史。

新增幂等 `POST .../applications/{aid}/evaluate`，请求revision/cases，返回绑定应用、版本、定义SHA256的强类型报告。评测使用既有RuleRun存储，不新增数据库schema。每次仍由后端重验项目、空间和责任人授权；空输入、空成功预期、过长参数和超过20条用例被拒绝。

固定样例在 `backend/tests/fixtures/knowledge_acceptance_v1.json`（12检索+10规则）；通过 `scripts/verify_integration.py` 的实际pytest/JUnit观察生成 `固定用例结果.json`，包含冻结文件SHA256、预期、实际、分子/分母及失败ID。实际强杀与维护包恢复也会核对报告原始内容。模型继续关闭，结果不代表泛化准确率、企业实数或真实模型效果。

应用入口修订：项目侧栏及工作台新增“应用生成 / 规则应用”，原节点保留；`section=knowledge&tab=applications` 可直达应用页签，带合法知识空间object/kind可直达该空间应用。刷新、切换空间及浏览器返回会保留页签；旧链接默认资料页。tab仅允许knowledge作用域，未选择空间时明确提示选择，权限仍由原接口重验。

主界面导航修订：首页和项目列表均常驻全部业务功能、应用及成员入口；点击使用当前业务项目，直接打开功能。首页与侧栏共用项目选择，进入业务再返回首页保留当前选择；切换项目清除旧对象与版本。无可访问项目仍展示功能并说明新建或联系管理员的下一步，权限始终由原服务端接口校验。
