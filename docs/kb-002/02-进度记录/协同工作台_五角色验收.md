## 先说清测了哪套界面

侧栏没有「协同工作台」。登录后「一期需求协同」下是三页：

| 入口 | 路由 | 数据 |
|---|---|---|
| 需求交底包 / 接口契约台账 / 例外与待办 | `#/requirements` `#/contracts` `#/exceptions` | **仅当前浏览器** `localStorage`（页上写明「数据保存在当前浏览器」） |
| 直接打开的协同工作台 | `#/collaboration` | **服务端** `/collaboration/*`，侧栏无入口 |

两套角色条、两套样例、互不可见。下面以**侧栏三页**为对确认清单的主验收（角色是具名的：市场李婉、商务陈曦、项目经理赵磊、设计周航、采购王磊），`#/collaboration` 单独记。

本轮在侧栏新建并走完的记录：`REQ-JY-2026-006`「验收走查·冷冻水支管」（草稿 → 已交底 v1 → 设计周航回写 v1）。在 `#/collaboration` 另有一条同名服务端记录（已交底、方案已回写、BOM 契约已接手、料行已询价）。

## 具体好用 / 缺失 / 易混

好用

- 侧栏角色条是具名岗位，不是一个裸下拉；禁用规则清楚（市场不能新建契约，设计/采购不能录入需求）。
- 例外类型与确认清单一致，处理按钮随角色变化，过滤开关有效。
- 契约表字段对齐企划附录，超时用「剩余/超时 N 天」而不是原始时间戳。
- `#/collaboration` 证明服务端能留下录入、交底、回写、接手、询价。

缺失

- 侧栏数据不进服务端，多人不能靠它少开会、少传微信。
- `#/collaboration` 不在导航里，和侧栏各说各的故事。
- 侧栏：草稿详情的黄条在未交底时仍写「需求已交底，但设计侧还没有形成…」。
- 服务端工作台：不能改正文只能「标记需求变更升版」；升版记录的操作者是登录身份而不是页上的工作角色；时间戳是 `2026-10-29T03:54:07.019397+00:00` 这种原文。

易混

- 两个「协同」：侧栏叫「一期需求协同」，地址栏 `#/collaboration` 才叫「协同工作台」。
- 例外副标题写「按当前角色过滤」，但「只看与我相关」默认关闭。
- 服务端「记催办」「阻塞」等二字按钮被排成「记催办」正常、但「接手」在无障碍名称里是「接 手」，采购料表按钮显示为「阻 塞」。

## 建议先改的 3 件事

1. **只留一条数据链。** 侧栏三页改读服务端协作数据（或下线 `#/collaboration`），去掉 localStorage 演示库。角色可以继续页内切换，但写入必须落库，换浏览器还能看见同一版本。
2. **修交底/回写弹窗被抽屉盖住。** 现在鼠标无法点到「确认交底」。同时：未交底不要对设计/采购展示为可当作正式口径的全文，或改掉「看不到正式交底版本」的文案；例外页默认打开「只看与我相关」。
3. **让 BOM 从需求包长出来。** 详情里一键建契约并自动带上需求包，不要手填内部 ID；采购能登记 ETA；例外行点进去就能处理；催办要在时间线上看得见。
