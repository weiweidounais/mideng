## 一期产品范围

### 做

1. **甲方需求入口（市场 → 商务）**  
   - 市场从甲方收到的需求/约束可结构化录入（项目、业主要点、工期/造价/技术约束、附件索引）  
   - 商务承接后形成「可对内交底」的需求包，状态可跟踪（草稿 / 已交底 / 有变更）  
   - 对应企划接口：**商机/需求交底**

2. **对内同步：商务 → 设计 / 采购 / 项目经理**  
   - 同一需求包一处发布，三方可见同一版本；变更留痕迹  
   - 目标：少开「市场商务设计采购再对一遍甲方说了啥」的会，少微信截图传需求

3. **方案优化输出**  
   - 设计（可会同商务）基于需求包给出方案要点/优化建议，回写到同一对象下  
   - 市场/商务可据此对甲方反馈；项目经理在例外页能看到「需求未交底 / 方案未回写 / 口径冲突」

4. **设计↔采购 接口契约台账**  
   - 字段对齐企划附录：触发、交付物、时限、质量、异常升级、Owner  
   - 主契约先做：**BOM/料表交接**（变更通知可作为事件类型，不做全公司变更大盘）

5. **例外 / 待办一页纸**（项目经理为主，市场/商务可看与己相关异常）  
   - 异常类型扩一层：需求未交底、方案未输出、版本冲突、料表超时、催料未回

6. **采购侧：料表/交期状态 + 少补台账**  
   - 以契约交付物为唯一待办来源；演示数据可手工录入，不强制一期对接用友

### 明确不做

- 不上一期：合同审查 AI、算量 AI、大而全双驾驶舱  
- 不强制：用友双向同步；CRM 全量替换  
- 不做：完整投标报价引擎（方案优化输出 = 要点/建议回写，不是自动出标书）  
- 不把「系统上线」当完成：没有少开会/少传口头需求/少催/少补台账的可感知证据，不算过

## 角色 × 界面

| 角色 | 打开中台做什么 | 成功长什么样 |
|---|---|---|
| 市场 | 录入/更新甲方需求要点与附件索引 | 内部同版本；少因不同步反复改方案 |
| 商务 | 确认交底包、推给设计/采购/项目经理；查看方案回写 | 交底一次到位；方案回写可视，少反复改 |
| 项目经理 | 例外/待办一页（含需求与方案异常） | 对接会减少或变短 |
| 设计 | 看需求包版本；回写方案优化要点；维护 BOM 契约 | 少因接口/需求不清返工 |
| 采购 | 看待交料表、交期；一处台账 | 少催、少另建 Excel |

## 信息流（一期必须跑通的一条演示链）

```text
甲方需求（市场录入）
  → 商务交底包（确认并发布）
  → 设计 / 采购 / 项目经理同步可见（同版本）

  → 商务/市场用于对甲方沟通
  → 设计↔采购 BOM 契约推进
  → 项目经理例外页能看到断点
```
