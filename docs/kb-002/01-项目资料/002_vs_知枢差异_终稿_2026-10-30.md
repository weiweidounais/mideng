# 密灯（原 02 / enterprise-kb）vs 知枢（zhishu-rag-platform）终稿

> 来源：工作群 2026-10-30；Grok Bot 汇总；用户确认可入库。  
> 讨论素材另见 [[002_vs_知枢差异讨论]]。对照仓：https://github.com/chusimin/zhishu-rag-platform

## 总判

同属 FastAPI+LangChain 单体，**不宜整仓二选一**。

- **知识底座取密灯（02）**：Qdrant + jieba/BM25、SSE 流式、DocMind、xyflow 节点图、协同旁路、`/api/observability/*` 与真实 `traceId`
- **交付壳取知枢**：评测门禁、Trace→Case、不可变版本/回滚、工作区 Token、业务端只见已发布
- **向量层**：先定 Qdrant **或** pgvector **一条主路径**，勿双轨

## 差异要点

| 维 | 密灯 (02) | 知枢 |
|----|-----------|------|
| 定位 | 企业知识中台 + 协同工作台（需求—契约—BOM） | FDE 应用交付闭环 |
| 检索 | Qdrant + 进程内 BM25 混合 | Postgres pgvector + 全文 RRF |
| 切块 | 3 档：recursive / parent_child / semantic | 9 方法 + 按文件配置/预览 + 关键词·问答对增强 |
| 应用 | xyflow 多节点 + 6 场景模板；SSE | Manifest 版本/门禁/分享/API；运行非流式；Chat Flow 未上 |
| 质量 | RAG 工作台指标；观测投影 MVP（真实 traceId 已落地） | 评测集发布门禁 + Trace→Case + 费用 |
| 租户 | 无多租户 | Workspace / API Token |

## 下一轮优先（群内共识）

1. 评测门禁 + 不可变版本/回滚（图编排可先挂门禁，不必先做 Chat Flow）
2. 按文件切块预览 + 分块增强；策略维持现有 3 档，别急堆 9 种
3. Trace→Case 回流；合仓时 **SSE 别丢**
4. 观测缺口是价表与渠道归因，不是「完全没观测」
