# API 密钥检查与保护

本轮在提交前使用 Gitleaks v8.30.1 检查公开仓库完整 Git 历史，并检查最终提交内容；报告只保留脱敏结果，原值不写日志。审计工具从官方 GitHub Release 下载并核对 SHA-256。扫描结果及范围见 [验收记录](../qa/collaboration-pilot/验收记录.md)。

API 接口地址、参数中的 `apiKey` 字段、模型 ID 和本机服务端口是代码功能的一部分。要隐藏的是实际密钥、访问令牌、私钥和管理口令。示例配置仅保留空值或明显的替换占位符，测试使用合成凭证。

## 当前保护

- `.gitignore` 排除 `.env`、运行目录、日志、数据库、初始口令、浏览器会话、私钥、备份与本地验收资料；仅保留 `.env.example` / `.env.compose.example`。
- 移除之前跟踪的运行日志，后续日志留在本机。历史日志已随完整历史扫描。
- `scripts/check-secrets.py` 检查已跟踪或暂存文件，识别常见令牌和硬编码凭证，并拒绝敏感文件名，不打印凭证值。
- 执行 `git config core.hooksPath .githooks` 后，提交钩子检查 Git 暂存区；钩子不会自动随 clone 启用，需在每台开发机设置。仍可被跳过，因此 GitHub 工作流再次检查。
- `.github/workflows/security.yml` 在 push / PR 中检查全部已跟踪文件与完整 Git 历史，Gitleaks 输出 100% 脱敏。新泄露会使检查失败；工作流不能自动撤回已经推送的密钥，提交前检查最重要。
- 服务端连接凭证保持加密存储，状态 / 导出 / 校验接口不返回明文；相关后端回归测试继续执行。加密密钥也必须独立保护，不能与公开源码一起上传。

## 开发与发布前

```sh
git config core.hooksPath .githooks
python scripts/check-secrets.py --staged
gitleaks git . --log-opts="--all" --redact=100 --no-banner
```

扫描器会有误报和漏报。测试中的明显假凭证、无密钥截图需人工复核；不要为通过检查而给整个项目加宽泛的 Gitleaks 忽略规则。图片、二进制和外部服务日志不属于文本扫描器能完整保证的范围。

## 如果以后真的泄露

先到对应服务商撤销旧凭证并生成新凭证，在本地 `.env` 或管理页面更新；再检查调用记录和使用范围。只把字符串改成星号、设为私有仓库、删除最新文件，都不会让历史凭证失效。

确有历史泄露时，另行协调使用 git-filter-repo 清理历史并更新远端与所有克隆；历史重写会影响协作者，本轮没有在未发现泄露时重写历史。GitHub 平台令牌、飞书授权等由本机凭证管理器 / CLI 管理，不应复制进源码或文档。
