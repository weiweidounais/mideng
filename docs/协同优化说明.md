## 先落地一条流程

范围选市场 → 商务 → 设计 → 采购 → 项目经理例外。不是同时建设 ERP、MES 和全集团经营平台。

同一需求的 `version` 表示业务依据版本；每条记录的 `revision` 表示数据库修改修订。每次 PATCH 都必须提供 `expectedRevision`，SQL 更新匹配失败返回 409，事件和业务修改在同一事务内保存。前端保留失败输入，不自动重放覆盖。

市场可录入、编辑草稿；商务发布和变更；设计回写方案、建立交付契约、登记及复核料表；采购验收、退回、登记交期及核对状态；项目经理登记决策和结果。管理员授予项目角色，并可选择角色演练。请求头只选择已授权角色，不能赋予权限。

状态链：草稿 → 商务交底 → 设计方案 → 设计交付 → 采购验收 → 询价 → 原系统下单 / 到货的人工记录。采购可以退回设计补齐。需求变更产生下一版，清空“当前方案”并保留旧快照，下游依据按版本自动显示待复核。

变更后必须重新交底、方案、设计交付、料表复核、采购验收。料表复核不修改采购已发生的状态或凭证。物料本身变动需新增当前版本行，旧订单应由采购在原系统处理、登记阻塞与说明；此版本不自动取消订单或执行高风险决定。

## 数据迁移与使用限制

历史需求按原项目名称归入确定的项目 ID，契约和料表保留，旧依据标为待复核；相同历史项目名称会归到同项目，管理员必须核对是否需要业务拆分。首次安装不生成带公司名字、人物和金额的演示数据。历史行缺少合法关联或字段时，应重新建立完整交付记录，不能把未知依据视为已确认。

当前人员标识仍来自服务端浏览器会话。与真人姓名的对应由管理员核对，没有企业身份认证的保证。会话默认 8 小时，到期、清理浏览器或更换设备后可能产生新身份，需重新授权。权限撤销在后续请求生效；已经被合法查看或下载的副本无法收回。管理员共享口令、多人身份审计以及大规模项目隔离需在正式上线前替换为实名账号体系。

事件台账是应用内追溯记录，不是防篡改的第三方审计系统。数据库管理员仍有能力修改数据库。导出是交接记录，暂不提供自动恢复导入；系统恢复使用完整数据库、附件及向量备份。

建议先用一个真实项目试点，确认责任人和字段口径，记录原先沟通耗时、退回次数及版本错误，再以同口径复测。资料中的预算、目标比例、时间和 ROI 示例未当作实际经营结果写入产品。
